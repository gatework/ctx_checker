## 已核对与落实

| 边界 | 发现 | 改动及证据 |
| --- | --- | --- |
| Profile → 可扩展解析器 → 多视图投影 | 解析器回调改写调用方维度数组，投影会变为其他视图 | 入口保存维度快照；回归先得到错误的 alarms 投影，修复后保留 counters/interfaces |
| RuntimeParser → 解析器 → 观测 | 回调清空维度数组后返回空观测；改写显式命令字符串会污染证据归属 | 保存维度及命令快照；两个回归分别先复现，再通过 |
| Reader → 单命令失败回执 | 失败回执允许多条完成步骤，被分类为普通命令失败 | 同时约束失败回执最多一个完成步骤；保留原始摘要，标记 invalid_command_result |
| Input → UTF-8/LF 正文 | 已归一化输入仍重复转码和执行无匹配替换 | 跳过冗余转换，只修改本层拥有的副本；编码、NUL、字节预算和非 ASCII 兼容编码回归通过 |
| 仓库开发入口 | 三个模块缺少各自的 AGENTS.md | 分别加入职责、所有权、不变量、命名规则、测试、基准、包验证及交付边界 |
| parse_outputs 整批来源 → 扩展回调 | 前一解析器可清空输出映射或改写后续正文；后续类型错误可能在已有解析副作用后才发现 | 整批校验并复制可变命令/正文；三个回归先复现，再验证保留来源、摘要和计数，非法正文在解析前拒绝 |
| Observation 字段归一化 → Immutable Hash 复制 | 每个字段反复分配临时二元素数组 | 直接填充新 Hash；既有深层、循环、复合键、共享引用及特殊 Hash 语义测试通过；完整链路分配测量见 pipeline-performance.md |

Input 微基准与复测方法见相邻 ctx_parser 的 `docs/input-performance.md`；完整链路测量见 [pipeline-performance.md](pipeline-performance.md)。不把函数级数据外推为设备性能。

## 设计与兼容性结论

- 底层保留来源与解析状态、上层决定适用性与健康策略的分工成立。Driver 借用会话，Collector 承担其创建流程的生命周期，解析器不承担连接与阈值策略。回调前固定输入是这次修复共同保护的不变量。
- Ruby `Data.define`、外层 freeze 不保证成员不可变；通过明确所有权的副本保护输入。Hash 重构避免临时数组，但保留独立普通 Hash、默认值去除、重复键覆盖及键先于值求值的行为；独立复核覆盖深度 0/63/64/65/100 与复合键，未发现新回归。
- 厂商解析器保持 CLI 命令映射名称。没有以命名统一为由破坏文件路径或引入兼容别名；通用行为继续位于 Input、Profile、Reader、RuntimeParser 和 Observation 边界。
- 已复核 Interfaces、Aggregation、Optics、Routing、Counters、DeviceCounters、Applicability、Evaluator、Report 的范围及失败传播。计数差值依赖时间、身份、单位/作用域及连续性；不完整观测不能证明健康或全设备缺失。
- 六个平台固定查询及 Radware 固件/动态端口查询共 77 条，逐条用空白、未知文本、CLI 拒绝、权限错误、NUL、ESC、非法 UTF-8 检查，共 651 个观测；均未返回虚假的 complete/not_applicable 或记录，原始摘要保留，非法字节归类 invalid_output。该临时审计补充既有厂商夹具测试，不代表任意设备格式均已覆盖。
- VXLAN 452、Wireless 314 项测试及完整 rake 通过；Baseline 已跟踪套件 1325 项及 lint/coverage_check/examples 通过。Baseline 原有未跟踪 `spec/backup_verification_spec.rb` 引用缺失的 `script/verify_backups.rb`，完整套件因此有 4 项失败；本轮保留该工作，未修改消费模块。
